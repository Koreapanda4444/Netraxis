# Netraxis

[English](README.md) | [한국어](README.ko.md)

네트워크와 인터넷 환경을 통합 관리하기 위한 **C++20 / Qt 6 Widgets 데스크톱 애플리케이션**입니다.

현재 기반 구조·영속성·플랫폼 프레임워크 단계인 **001~028**이 구현되어 있습니다. 앱 시작·종료 및 중복 실행 처리, 동시 실행 수와 대기열이 제한된 비동기 작업, 설정 검증·저장, 민감정보를 제외하는 이벤트 로그, 네트워크 도메인 타입, 관측 근거 메타데이터, SQLite 마이그레이션과 저장소, 저장된 Workspace 관리 및 관측 이력 보관 정책을 제공합니다.

기본 인터페이스와 주소 목록은 Qt의 네이티브 제공자를 통해 조회할 수 있습니다. OS별 상세 수집과 설정 변경은 이후 단계에서 구현합니다. 화면에서는 사용할 수 없는 기능과 검증하지 않은 상태를 명시적으로 구분합니다.

## 빌드

다음 개발 환경이 필요합니다.

- C++20 지원 컴파일러
- CMake 3.24 이상, Ninja
- Qt 6.4 이상: Widgets, Network, SQL 모듈과 SQLite 드라이버

Qt가 자동으로 검색되지 않으면 `CMAKE_PREFIX_PATH`에 Qt 설치 경로를 지정합니다.

```sh
cmake --preset release
cmake --build --preset release
```

| 운영체제 | 실행 경로 |
|---|---|
| Linux | `build/release/netraxis` |
| Windows | `build/release/netraxis.exe` |
| macOS | `build/release/netraxis.app` 앱 번들 |

Windows에서 Qt MSVC 패키지를 사용하는 경우 MSVC 개발자 셸에서 빌드해야 합니다. CI에서는 Qt 6.8.3을 사용하여 세 운영체제의 구성·컴파일·앱 실행을 확인합니다.

`--platform-report` 옵션은 선택된 제공자와 실제 조회한 인터페이스 수를 JSON으로 출력합니다. 조회할 수 없으면 0이 아닌 종료 코드를 반환합니다.

## 로컬 데이터

설정, SQLite 데이터베이스, 순환 저장되는 앱 이벤트 로그는 Qt가 제공하는 사용자별 애플리케이션 디렉터리에 저장됩니다. 비밀번호와 토큰은 데이터베이스나 이벤트 로그에 기록하지 않으며, 장비 모델에는 자격증명을 가리키는 참조 ID만 보관합니다.

관측 이력 정리는 앱 시작 시와 실행 중 15분마다 수행합니다. 저장된 보관기간과 저장 용량 기준에 따라 관측값을 정리하며, 등록된 프로필은 유지합니다. 설정 화면의 별도 삭제 기능에서는 사용자 확인을 거쳐 저장된 네트워크 기록과 마이그레이션 백업을 삭제할 수 있습니다. SQLite의 삭제 데이터 정리(`secure_delete`), WAL 축소, 데이터베이스 압축을 적용하지만, 물리 저장매체에서의 완전한 소거나 시스템 백업 삭제까지 보장하지는 않습니다.

지원되는 기존 데이터베이스의 스키마를 업그레이드할 때는 접근이 제한된 복구용 사본을 생성합니다. 정리 과정에서는 불필요해진 백업을 삭제하고, 알 수 없거나 더 새로운 스키마 버전은 거부합니다. 잘못된 설정은 오류로 표시하며, 유효한 설정을 저장하기 전에는 자동 데이터 정리를 활성화하지 않습니다.

## 플랫폼 프레임워크 (020–028)

개요 화면에서 선택된 플랫폼·제공자, 현재 프로세스 권한, 기능별 지원·수집 상태와 실패 원인, 관측한 인터페이스·주소, 스냅샷 신선도를 확인할 수 있습니다. 수집은 백그라운드에서 실행하며 새로고침·취소를 지원합니다. 사용할 수 있는 시스템 이벤트는 짧은 지연 후 다시 수집하도록 요청하며, 인터넷이나 서비스 연결 성공을 뜻하지 않습니다.

백엔드 작업은 Coordinator별로 직렬화합니다. 취소와 시간 제한은 협력 방식이므로 동기 네이티브 호출을 강제로 중단하지는 않으며, 호출은 UI 스레드 밖에서 실행합니다. 정규화 시 출처와 관측 시각을 보존하고 잘못된 선택 필드는 부분 관측으로 표시합니다. 변경 트랜잭션 계약은 복구 가능한 사전 설정을 확보하고, 변경·복구 요청 각각에 승인을 연결하며, 상태 드리프트를 차단합니다. 적용 완료·복구 완료·복구 대기·복구 실패를 구분합니다. 이 단계의 실제 네이티브 설정 변경은 미지원입니다.
